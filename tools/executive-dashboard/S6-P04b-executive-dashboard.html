Executive Dashboard

An executive does not need another chart; they need seven numbers they can trust in a thirty-second read — total case volume, the backlog, escalations, what has closed, the escalation rate, average age, and how many cases are breaching SLA — each one calculated live from the case register underneath, and a regional table that breaks the same register down the same way. This dashboard is that read, over a 36-case sample register. Every case, date and figure in it is sample data.

Provenance & Operating Record: Built from 15+ years in commercial contracts, deal desk, and revenue operations across contracts up to $300M and 3,000+ SKUs under management. This workbook is an equivalent sample built in October 2026 to pair with the Executive Dashboard portfolio PDF; the original dashboard was built in a CRM system and no workbook version existed. The CRM's raw case export is not in this workbook and is never displayed — every case, date, and figure on this page is fictional sample data.

Directions

Directions: The Case Data tab is the register — edit statuses, regions, dates, and SLA targets there. The Executive Dashboard tab recounts it into the seven headline KPIs, and the Regional Performance tab rolls the same register up by region: totals, backlog, escalated, closed, average days, and breaches per region. Nothing on the two rollup tabs is typed — change a register row and both tabs move. Open cases age against today's date, the way the workbook's formulas do it, so the age-driven numbers move with the calendar.

Inputs, logic, limits

          
In the dashboard's own words — Inputs: the Case Data register rows (36 sample cases: Case ID, Region, Queue, Case Type, Priority, Status, Opened, Closed, SLA Target in days). Logic: live KPI formulas over the register — counts by status, SLA flags, and regional rollups on the Regional Performance sheet; figures recalculate from the register. Limits: sample data only (36 cases); no charts in the original; figures move only when register rows change. Two definitions worth naming plainly: this dashboard's backlog line counts Open + In Progress, and says so in its own label — a narrower, self-described definition than the not-Closed count used in the Case Operations tool (S6-P03.3), and each workbook keeps its own words rather than borrowing the other's. The escalation rate is escalations as a percentage of total volume, rounded to one decimal by the workbook's own formula.

          
    
            
  • Age / Resolution: IF Status = "Closed" → Closed − Opened; ELSE → TODAY() − Opened
    • 
            
  • SLA Flag: IF Age > SLA Target → "BREACH"; ELSE → "Within SLA"
    • 
            
  • Regional Backlog: COUNTIFS(Region, Status <> "Closed")

Built as an equivalent sample

          
The original dashboard behind the portfolio PDF was built inside a CRM system — the metrics an executive team actually watched: open and closed case volumes, backlog and queue monitoring, case aging and escalation tracking, regional performance, workload distribution. No workbook version of it existed, so this workbook is an equivalent sample, built in October 2026 to pair with that PDF: it mirrors the same metrics as live formulas over a sample register, so the structure and the controls can be inspected and exercised. The CRM's raw case export is not in this workbook and is never displayed — the 36 cases on the Case Data tab are the sample's own illustrative data, labeled as such in the file itself.

        

        

          
Why live reconciliation matters

          
That distinction is the point of showing it this way. A screenshot of a CRM dashboard proves a dashboard existed once; a live workbook proves the numbers reconcile — the regional table's totals sum to the dashboard's volume, the breach count equals a hand count of BREACH flags in the register, and editing one register row moves every dependent figure in the open. The executive read is only worth thirty seconds if the arithmetic under it survives being touched.
