Proof of Work · Contract Operations

Contract Migration & Triage Tracker.

Moving contracts from one system to another is where migrations quietly stall: a stage slips, an owner is unclear, a target date moves and nobody flags it. This tracker is the control sheet for that work — one row per migrating contract with where it is moving from and to, its stage, owner, target date, and status, a Risk Flag that reacts the moment a status changes, the metadata that matters when the contract comes back up (governing law, effective date, auto-renewal, liability cap), and a priority tier the operator assigns. Behind it sit the governance references: an approval-routing matrix by discount band, a RACI matrix for the work itself, and an exception log. Every customer, contract, and figure in it is sample data.

Directions: Each row is one contract migration (sample data): where it is moving from, where it is going, its stage, owner, and target date. Change a row's Status and watch the Risk Flag react — set a migration to At Risk and the flag flips to REVIEW; mark it Complete and the flag reads Done; anything else reads Monitor. Use the Approval Routing table to see who must approve at each discount band, and the RACI Matrix to see who owns each step of the work.

Inputs, logic, limits

Inputs: the tracker row fields — contract ID, customer, from system, to system, migration stage, owner, target date, status — plus the metadata columns and the Tier, all typed in by hand. Nothing in this tool extracts terms from contract documents, and the Tier is the operator's judgment, assigned by the user — the tool never auto-tiers a contract. Logic: the only live logic is the Risk Flag formula (At Risk → REVIEW, Complete → Done, anything else → Monitor) and the count-by-tier summary beneath the rows. The Approval Routing and RACI tabs are static reference tables, and the Exception Log is a record, not a calculator. Limits: sample data only — six contracts, three exceptions. There is no dashboard or velocity roll-up in this workbook, and the page does not promise one.

The reference tables behind the tracker.

Approval Routing. Who must approve or review a deal at each discount band — ≤10% runs standard, then 11–20% and 21–30% add reviewers, and anything over 30%, or carrying prepay or most-favoured-nation terms, routes to the top — across Deal Desk, Finance, Legal, and VP Commercial.

RACI Matrix. For each of the seven migration activities, who is responsible, accountable, consulted, and informed — so a stalled step has a name on it before it stalls.

Exception Log. The pricing and concession exceptions the migration surfaces, each with its approver and status — the audit trail for every deliberate departure from standard terms.
